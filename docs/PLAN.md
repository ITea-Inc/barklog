# BarkLog — план проекта

Приложение анализирует аудиозапись (или живую запись с микрофона), пока собака
остаётся дома одна, и показывает: сколько времени она лаяла, скулила, выла,
когда это происходило и как меняется картина день ото дня.

Вся обработка — **на устройстве**, без облака. Ядро на Rust, сначала Android,
затем iOS без переписывания логики.

---

## 1. Что видит пользователь

**Вход:**
- импорт файла с диктофона (m4a/AAC, mp3, wav, ogg/opus, flac);
- или встроенный режим «Я ушёл» — приложение само пишет и анализирует на лету.

**Результат сессии:**
- общее время сессии и время «активности» собаки;
- круговая диаграмма в процентах: лай / скулёж / вой / рычание / тишина / прочий шум;
- таймлайн сессии — цветная полоса, где видно, *когда* был лай и скулёж;
- список эпизодов: начало, длительность, тип, интенсивность — с прослушиванием фрагмента;
- столбчатая диаграмма по часам (в какие часы активнее всего);
- ключевые цифры: число эпизодов, самый длинный эпизод, через сколько минут
  после ухода начался первый лай, когда собака успокоилась.

**История:**
- тренды по дням/неделям (растёт или падает тревожность);
- сравнение сессий между собой.

## 2. Классы звуков

| Класс     | Что входит                                    |
|-----------|-----------------------------------------------|
| `Bark`    | лай, тявканье                                 |
| `Whine`   | скулёж, поскуливание                          |
| `Howl`    | вой                                           |
| `Growl`   | рычание                                       |
| `Silence` | тишина / фон ниже порога громкости            |
| `Other`   | всё остальное: улица, соседи, ТВ, бытовые шумы |

Проценты считаются от общей длительности записи; отдельно показываем проценты
только среди «собачьих» звуков.

## 3. Архитектура

```
┌──────────────────────── UI (тонкий слой) ────────────────────────┐
│  Android: Kotlin + Jetpack Compose     iOS: Swift + SwiftUI      │
│  экраны, графики, foreground-сервис,   экраны, Swift Charts,     │
│  выбор файла, уведомления              background audio          │
└───────────────────────────┬──────────────────────────────────────┘
                            │ UniFFI (автогенерация Kotlin/Swift биндингов)
┌───────────────────────────┴──────────────────────────────────────┐
│                      Rust core (вся логика)                      │
│  decode → resample 16 kHz mono → окна → модель → сглаживание →   │
│  эпизоды → статистика → SQLite                                   │
└──────────────────────────────────────────────────────────────────┘
```

**Почему так:** всё, что сложно и важно (аудио, ML, статистика, хранение),
пишется один раз на Rust и одинаково работает на Android, iOS и десктопе.
Нативный слой — только экраны и то, что требует системных API (фоновая запись,
разрешения, выбор файлов, уведомления). Именно фоновая запись на мобильных
плохо дружит с кроссплатформенными UI-фреймворками, поэтому UI нативный.

Если захочется 100% Rust, UI-слой можно заменить на Dioxus/Slint — ядро от
этого не меняется.

## 4. Пайплайн анализа

1. **Декодирование потоком.** 8 часов записи = ~1.8 ГБ в f32 — целиком в память
   не грузим. Читаем пакетами через symphonia, сразу ресемплим в 16 кГц моно.
2. **Окна.** 0.96 с с шагом 0.48 с (формат YAMNet).
3. **Энергетический гейт.** Окна тише порога сразу помечаются `Silence` и не идут
   в нейросеть — это экономит 70–90% вычислений на типичной записи пустой квартиры.
4. **Классификация.** YAMNet (AudioSet, 521 класс), сеть реализована на Rust
   напрямую (MobileNet v1, ~3.7 млн параметров), без ONNX/TensorFlow. Нужные
   классы AudioSet: *Dog, Bark, Yip, Bow-wow, Howl, Growling, Whimper (dog)*.
   Маппинг 521 → 6 наших классов + порог уверенности.
5. **Персональный классификатор (этап 4).** Поверх 1024-мерных эмбеддингов YAMNet
   обучается маленькая логистическая регрессия на разметке пользователя
   («это скулёж», «это не моя собака»). Обучение прямо на телефоне, секунды.
   Это главный способ поднять точность скулежа — у YAMNet он распознаётся слабо.
6. **Сглаживание.** Медианный фильтр / гистерезис по последовательности
   предсказаний, чтобы не было «мигания» классов.
7. **Эпизоды.** Склейка соседних окон одного класса; паузы < N с (по умолчанию 3 с)
   внутри эпизода не разрывают его; эпизоды короче минимума отбрасываются.
8. **Статистика.** Длительности и проценты по классам, по часам, эпизоды,
   задержка до первого лая, самый длинный эпизод, «индекс тревожности».
9. **Сохранение.** Сессия + эпизоды + агрегаты в SQLite; опционально — короткие
   аудиоклипы эпизодов (Opus) для прослушивания.

Анализ идёт в фоне с прогрессом и возможностью отмены; результат частично
доступен ещё до конца обработки.

**Ориентир производительности:** 8 ч записи на среднем Android-телефоне —
до 3–5 минут с энергетическим гейтом. Проверяем на этапе 1 через CLI.

## 6. Этапы

### Этап 0 — каркас — готово (CI заработает после публикации на GitHub)
- git, workspace, CI (GitHub Actions: `fmt`, `clippy -D warnings`, `test`, сборка APK);
- Git LFS для моделей.

### Этап 1 — ядро + CLI (MVP на компьютере) — готово, разбивка проверена на настоящей записи
- декодирование, ресемплинг, окна, энергетический гейт;
- YAMNet на чистом Rust, маппинг классов;
- эпизоды, статистика;
- `barklog-cli analyze recording.m4a --html report.html` — отчёт с диаграммами;
- **прогнать на реальных записях твоей собаки** и оценить точность;
- юнит-тесты на синтетике + небольшой размеченный эталон.

> Готово, когда CLI на настоящей записи выдаёт правдоподобные проценты
> и таймлайн.

### Этап 2 — Android MVP — готово
- сборка `.so` через `cargo-ndk` (arm64-v8a, x86_64) + Kotlin-биндинги UniFFI;
- экраны: список сессий → импорт файла → прогресс → отчёт (таймлайн, доли, по часам, эпизоды);
- анализ в фоне через WorkManager, прослушивание эпизодов из исходного файла;
- SQLite-хранилище.

### Этап 3 — живая запись «Я ушёл» — готово, ждёт проверки на телефоне
- foreground-сервис с `foregroundServiceType="microphone"` и wake lock;
- захват звука платформой (AudioRecord на Android, AVAudioEngine на iOS),
  весь анализ — в Rust: `LiveSession` принимает PCM и считает на лету;
- сырое аудио **не храним** — только фрагменты вокруг звуков собаки
  (8 ч сырого звука — почти 1 ГБ); эпизоды слушаются из этих фрагментов;
- экран записи: счётчик ленты, «сейчас тихо / собака лает», голос, эпизоды, таймлайн;
- «Я вернулся» — остановка и сразу отчёт;
- `LiveSnapshot` — компактный снимок текущего состояния: его же показывает
  экран записи, и его же этап 3б отправляет на другой телефон;
- для разработки: в debug-сборке вместо микрофона можно «проиграть» файл.

### Этап 3б — удалённый просмотр с другого телефона — готово (пуши ждут тарифа Blaze)
Пока телефон записывает дома, со своего второго телефона (или телефона члена
семьи) под тем же аккаунтом видно, что происходит прямо сейчас.

- **Что видно:** идёт ли запись, сколько прошло, голос собаки за всё время
  и за последние 15 минут, «сейчас лает / тихо», последний звук N минут назад,
  таймлайн сессии. Обновление раз в 30 с и сразу при начале/конце эпизода.
- **Что передаётся:** только `LiveSnapshot` — цифры и таймлайн (сотни байт).
  Звук не уходит с телефона. Опционально, по явному включению — короткие
  фрагменты эпизодов, чтобы послушать с другого телефона.
- **Пуш-уведомление** на второй телефон, если собака лает дольше X минут подряд
  или скулит дольше Y минут (пороги в настройках).
- **Аккаунт:** вход через Google (Android) / Apple (iOS) на обоих телефонах;
  записывающий телефон публикует, остальные устройства аккаунта подписаны.
- **Бэкенд, рекомендация — Firebase:** Auth (вход), Firestore (документ
  `users/{uid}/live/{deviceId}` с подписками в реальном времени), Cloud
  Messaging (пуши), одна Cloud Function — правила пушей. Есть SDK для Android
  и iOS, бесплатного тарифа с запасом хватает (один документ ~раз в 30 с).
  Снимок сериализуется в Rust, поэтому позже можно заменить Firebase своим
  сервером (Rust + axum + WebSocket) без изменений в ядре.
- **Ограничения:** нужен интернет на записывающем телефоне; при обрыве связи
  запись и анализ продолжаются локально, на втором телефоне показывается
  «нет связи с N минут» и последний полученный снимок.
- Экран на втором телефоне — тот же экран живой сессии, что и на записывающем,
  но только для чтения.

### Этап 4 — персонализация и точность — готово
- разметка эпизодов: долгое нажатие → лай / скулёж / вой / рычание / не собака,
  отчёт пересчитывается сразу, «не собака» можно вернуть;
- хранение окон (4 байта на окно) и эмбеддингов YAMNet для собачьих и спорных окон;
- личная модель (softmax-регрессия на эмбеддингах) обучается на телефоне за секунды,
  пересчитывает все записи и разбирает новые; модель хуже 60 % на проверке
  не применяется;
- настройки: чувствительность (порог «это собака»), склейка пауз и самый короткий
  эпизод; меняются задним числом — сохранённые окна перерешиваются по эмбеддингам
  YAMNet, без повторного анализа (4-часовая запись — доли секунды на ПК).

### Этап 5 — дополнительные функции — частично готово
- готово: тренды по дням/неделям и сравнение сессий (экран «Динамика»), заметки к
  сессии, экспорт — PDF-отчёт о записи и CSV (эпизоды записи, все записи), фильтр чужих
  собак (отметка «чужая собака» — отдельный класс личной модели, время чужих собак в
  отчёте отдельной строкой, в голос своей собаки не входит);
- уведомления на часы (продолжение этапа 3б);
- несколько профилей собак;

### Этап 6 — iOS
- сборка `.xcframework` (aarch64-apple-ios, aarch64-apple-ios-sim) + Swift-биндинги;
- SwiftUI-экраны поверх того же FFI;
- фоновая запись через `AVAudioSession` (background mode audio);
- **требуется Mac с Xcode** для сборки и подписи.

## 7. Риски

| Риск | Что делаем |
|------|------------|
| YAMNet плохо отличает скулёж | персональный классификатор (этап 4), эталонный набор для оценки |
| Чужие собаки / ТВ с собаками | персональная модель + разметка «не моя собака» |
| Android убивает фоновую запись | foreground-сервис, инструкция по отключению оптимизации батареи |
| Долгий анализ 8-часового файла | потоковая обработка, энергетический гейт, многопоточность |
| Размер модели (~15 МБ) | приемлемо; при необходимости квантизация |
| Сборка iOS без Mac | откладываем до этапа 6, ядро тестируем на десктопе |
| Запись прервана (звонок, система убила процесс) | foreground-сервис + wake lock; позже — контрольные точки на диск и восстановление сессии |
| Удалённый просмотр зависит от интернета и Firebase | только агрегаты, локальная работа без сети, снимок в Rust — бэкенд заменяем |

## 8. Ближайший шаг

1. Проверить этап 3 на настоящем телефоне: многочасовая запись в фоне с
   выключенным экраном, расход батареи, звонок во время записи.
2. Этап 3б: проверить вход через Google и просмотр на двух настоящих телефонах;
   при желании — тариф Blaze и развёртывание функции пушей.
3. Первые настоящие сессии: отметить эпизоды и обучить личную модель.

Первая настоящая запись (4 ч, шумный диктофон с фоном около −41 дБ): разбивка
на эпизоды подтверждена. Фон громче порога гейта теперь идёт в сеть и, если собаки
нет, считается тишиной, а не «другими звуками».

Замеры: 40 минут записи анализируются за ~1 с на ПК и за ~5 с на эмуляторе.
Живая запись хранит только фрагменты с собакой: на тестовой 40-минутной
сессии — 2,7 МБ вместо ~77 МБ для полного WAV.
